Rank #1 · Top recommendation Strong

The wire contract is folklore, not a module

C7 · VisionBrain: live_engine.py:255-320, static/index.html:2239-2249, 1935, 1914 · Bridge: protocol.py:18-381, dashboard/index.html:245-248 · Android: BinaryFrameCodec.kt:8-26, BridgeWebSocketClient.kt:100-126

Problem

The >III binary frame codec is independently implemented 5 times in 3 languages. The detections JSON has two dialects (score rounded to 3 vs 4 decimals; direction/color_id vs source/track_state/stale_ms), and the Ground Control dashboard carries the fossil fallback msg.detections || msg.items to bridge the split. Capability geometry.polygon_q16.v1 is advertised by Kotlin, parsed by Kotlin, sanitized by the bridge — but emitted by nothing and absent from SERVER_CAPABILITIES, so negotiation can never accept it. The local engine ignores hello entirely. One recent wire change ("emit mask polygons") touched 6 files in one repo while parallel machinery already existed in the other.

Solution

Move the codec, detections envelope, limits, and negotiation into an MLX-free module in the visionbrain package (exactly CM-02's "Python definitions belong in VisionBrain"). vb_bridge/protocol.py becomes a thin re-export — the pattern already proven by the bridge's sam_tracking.py/tracking.py shims. Freeze one golden fixture corpus (timestamp-wrap, polygon bounds, dialect cases) consumed by pytest, the Kotlin tests, and a tiny JS harness. Fold in: emit or delete polygon_q16.v1; pin one detections dialect and retire the fossil fallback.

Rank #2 Strong

One live-loop brain, not two

C8+C5 · Bridge: brain.py:76-79, 137-160, 860-957 · evidence.py:21-52 · VisionBrain: live_engine.py:1110-1126, 2569-2631 · vlm_registry.py:165-188

Problem

brain.py (996 lines) and live_engine.py (2,727) implement the same loop interface — arm-state machine, one-in-flight ask/report slot, GPU admission, detections publication — with already-diverged error modes for identical controls: the bridge answers a second ask with ask_ack + ok:false; the engine pushes {"type":"error"} in some paths and ask_ack in others. The dashboard carries polyglot glue handling all three shapes. Meanwhile the unification pass left stragglers: evidence.py's detection-line formatter duplicated verbatim in vlm_registry.py, and brain.py re-implements mask_to_polygon (with its own MAX_POLYGON_POINTS = 64) even though it already imports from visionbrain, where the canonical version lives.

Solution

Phase 1 (mechanical, now): one formatter, one polygon tracer, one ask/report rejection ladder, one error dialect on the wire. Phase 2 (after mission_runtime lands, so the core isn't built twice): an MLX-free live-loop module — arm state + ask slot + publication hooks with injected perception/clock/publish adapters — of which brain.py and live_engine's worker become the field and desktop adapters. This is the same deepening detection_core.py and live_tracking.py already demonstrated.

Rank #3 Strong

One reasoner seam — the seam is real, the code is copy-paste

C1 · gemma_inference.py:446-942, 339-364, 47 · vlm_registry.py:53-65, 130-137, 205-212 · live_engine.py:1136-1150 · loader.py:24

Problem

Grounded VLM ask/report exists as 8 near-identical functions (4 backends × ask/report in gemma_inference.py) plus two more chat transports (vlm_registry._generate, agent_loop.VLMClient). Two stacks do the same job with incompatible interfaces (image_path: str → GemmaResponse vs image: PIL → str), duplicated system prompts, and a byte-identical detection-counts loop in two files. Worst: _gemma_cache is a second model-residency authority bypassing model_host.HOST — the module that exists precisely to prevent two resident copies — and the Gemma repo id is defined twice.

Solution

One reasoner seam: ask(...) / report(...) with adapters chosen by a registry (custom → ollama → remote → mlx-local). Prompts, style dict, counts rendering, and usage normalization hoist into the shared front; each adapter shrinks to "translate messages, parse response". vlm_registry's keys become checkpoint selection inside the mlx adapter, and its model_host.HOST residency becomes the whole stack's residency — the _gemma_cache bypass disappears without editing model_host.py (judge ruling: compliant with the ADR).

live_engine.py — the 2,727-line room where everything meets

C2 · live_engine.py:2282-2287 (globals), 1912-2273 (_run), 1942-1943+2480 (private reach-ins) · tests/test_live_engine.py

Problem

Engine state lives in six module globals shared between the WS handler and the worker; ordering invariants are conventions enforced by comments, not by a module. The interface is not the test surface: the test fixture must monkeypatch all six globals, tests reach into worker._jpeg_quality, worker._frame_lock, and a private sentinel — and every test that could exercise the frame pipeline replaces it instead. The actual detect → triggers → events → capture → encode pipeline (_run) has zero coverage — exactly where SIMPLIFICATION_SPEC §3–§5 behavior lives. It also re-implements ~100 lines of LiveSamTracker semantics that have already drifted.

Solution

A LiveEngine object: start / apply(action, payload) / evidence_snapshot / subscribe / stop. The three _pending_* globals become engine state; the WS handler shrinks to an adapter (validate → apply → render). An injectable source/sink makes the pipeline testable with fake frames. A dependency-free TriggerEngine.update(items, ts) → events folds the already-extracted zone/dwell/direction state machines.

Consume only with injected thread-local backbone_fn/detect_fn, or record a spec amendment first. Don't block the engine-object and testability work on this.
Strong

The web tier speaks to the pipeline in argv

C3 · web_app.py:334-597 (9 endpoints) · cli.py:275-737 (cmd_analyze), 882-1051 (argparse)

Problem

Every job endpoint hand-builds [python, "-u", "-m", "visionbrain", "analyze", …], mirroring argparse flag strings. The CLI's argparse block is a load-bearing wire protocol with no module behind it: renaming --backbone-every breaks the UI at runtime, not at import. Results come back as positional file paths and magic dict keys. cmd_analyze is a 462-line fused function whose only tests are --help smoke tests — the module is the wrong shape, so tests reach for argv.

Solution

Typed options + structured results (run_analyze(AnalyzeOptions) → AnalysisResult — the shape PilotReport and FrameScores.to_dict already model successfully). CLI becomes an adapter (argparse → options → printer); web becomes a second adapter under the existing JobQueue. Phase 1 is the seam only — subprocess isolation stays (it's load-bearing for cancel/memory safety); in-process execution is a separately measured later step. This seam is also the natural home for CM-04's inference admission gate.

Adapter count: two real callers today (HTTP console, terminal CLI) — a real seam waiting to be named.

Ruling (jury C proposed, judge upheld): target A — the mission runtime hosted inside the bridge process, exactly as NEXT_DEVELOPMENT_SPEC CM-00 already proposes — the bridge keeps capture/transport/archive and shrinks to adapters; the visionbrain runtime owns mission state and decisions. Execute CM-02 as C's first steps: a dependency-free contract module with golden fixtures consumed by pytest and Kotlin conformance tests (no codegen in v1 — hand-maintained Kotlin against shared fixtures; revisit codegen only after a second dialect-drift incident).

B is not rejected — it's shelved with a written trigger. Revisit the monorepo when any two of: (i) a second cross-repo contract breakage despite fixtures, (ii) recurring same-commit cross-repo changes to mission_runtime/mission_store, (iii) packaging drift recurring after the dependency-declaration fix. Signal already visible: the repos cross-link each other via ../visionBrain-bridge/ — a path that doesn't match the actual directory case.

The structural gap A leaves open: "importable without MLX" is currently a convention (lazy imports), not a packaging fact — pip install visionbrain drags fastapi/opencv/supervision, and one careless top-level import mlx_vlm breaks the field host boot (it already happened once; a CI commit patched around it). The contract package + a CI bare-venv import job turns the convention into a guarantee. This is the single most load-bearing fix for everything CM-00 promises.

Top recommendation

Make the wire contract a real module in the visionbrain package, proved by one golden fixture corpus (C7) — preceded by the do-now batch (C9's dependency declaration, C4's deletion, C6's vocabulary single-sourcing), which gates nothing and takes a day.

Why this first: it has the highest measured blast radius (five codec implementations in three languages; one wire change already cost six files in one repo while parallel machinery existed in the other), it is exactly CM-02's mandate stated as code, and everything later — the mission runtime, CM-05's clients, the versioned handshake — is built on top of it. It converts the partnership's riskiest knowledge from prose in AGENTS.md into a fixture-tested interface before CM-05/CM-08 build more clients on the wire. The friction is not hypothetical: a capability is advertised and parsed by three implementations and emitted by none; the dashboard carries a fossil fallback for a dialect split that should not exist; and the only version "handshake" today is a shell banner on the M2.

One sentence verdict on the partnership itself: the two-repo deployment split is earning its keep; the seam between them — currently maintained by prose — is not. Land the contract module and the monorepo question becomes a CI/HR decision, not an architectural one.
